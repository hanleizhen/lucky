# CNC 智能程序单

Windows 桌面工具。将一个或多个 `.NC` 文件拖入窗口后，程序会按顺序解析并写入提供的 `CNC程序单.xlsx` 模板：

- 程序名称：`B7:B25`
- 刀具类型：`C7:C25`
- D：`D7:D25`
- R：`E7:E25`
- 加工 DATA：`F7:F25`
- 最低 Z 深度：`J7:J25`

程序不会保存或覆盖源模板。首次启动会把随程序附带的模板复制到 `%LOCALAPPDATA%\CNCProgramSheet\templates\CNC程序单.xlsx`；此后的升级只更新安装目录，绝不会写入这个用户数据目录。

## 本地运行

```powershell
py -3.12 -m pip install -r requirements.txt
py -3.12 main.py
```

拖入 `.NC` 文件后，程序会按文件名中的数字自然升序填写，例如 `O-1.NC`、`O-2.NC`、`O-10.NC`。同一复合程序中的多把刀仍按原刀号顺序保留。带 `.NC` 后缀的文件会隐藏模板中的刀具号；无后缀铜工程序则保留 `T1`、`T2` 等刀具号。也可以从资源管理器复制一个或多个 NC 文件后，在软件窗口按 `Ctrl+V`；复制整段 NC 程序文本后按 `Ctrl+V` 也会自动导入并解析。粘贴的程序文本会安全保存到 `%LOCALAPPDATA%\CNCProgramSheet\pasted_nc`，以便后续“重新解析”，且软件升级不会删除它。可以在左侧解析表或右侧 Excel 预览中修正所有自动填写项；双击“已导入 NC 文件”中的一项还可以查看并直接修改对应 NC 源程序。右侧预览使用与 Excel 模板一致的黑色加重格线。右键程序行可在下方插入空行，或插入红色的 `❮Y⟲180°❯`、`❮X⟲180°❯`、`❮Z⟲180°❯` 提示行；选中这类行后按 `Delete` 可取消。首次点击“完成并保存”时可设置固定保存文件夹，之后自动保存到该文件夹；使用“保存位置”可随时更改。在模板顶部右侧的空白名称框（`J1`）输入名称后，导出文件会命名为“输入名称_当天日期.xlsx”；留空时仍按原先的 NC 程序名自动命名。

## M06、M304 与铜工程序修改

顶部的 `M06`、`M304`、`铜工` 三个按钮分别打开独立的程序修改页。每一页都可以拖入、选择或按 `Ctrl+V` 粘贴 NC 文件/程序文本；左侧会以浅蓝色 `M06`、`M304` 或 `TG` 标记，右侧可以在执行前查看和手动修改 NC 内容。执行后会自动通过原有解析流程填写程序单，主窗口的已导入文件列表也会保留相同的浅蓝色来源标记。

三个修改规则以原桌面快捷方式为基础，不做“智能修正”；M06 按本软件要求统一输出 Windows CRLF 换行：

- `M06`：只处理 `.NC`，原地覆盖；所有含有 `M6` 的整行都会被删除（包括原快捷方式本来也会误命中的 `M60`）。输出统一使用 Windows `CRLF` 换行，避免机床或传输软件因 `LF` 格式产生兼容性问题。多刀程序在本次软件会话内仍按执行前的刀具段分别填写程序单，磁盘中的 NC 文件不额外补回任何 M6 行。
- `M304`：原地覆盖；只在原脚本指定的第一个 `G43...M8` 与行尾 `M5` 后插入指令，已有标记时不补齐缺失的配对行。
- `铜工`：只处理 `.NC`；在原文件夹生成同名无后缀程序，按原规则写入安全行并将最后一个 `M30` 改为 `M99`，然后删除原 `.NC`。原快捷方式可能产生的重复安全行也会保留。

这些操作与原快捷方式一样会覆盖/删除程序文件且不建立备份；请先在右侧编辑器检查内容，再点击“执行修改并填写程序单”。从资源管理器复制的 NC 文件会在原文件夹处理；直接粘贴的程序文本本身没有原始文件夹，软件会先要求选择真实的 NC 保存位置，再按该位置执行覆盖规则。

## 图片插入

1. 在右侧 Excel 预览中点击图片要停靠的单元格。
2. 从资源管理器复制 PNG、JPG、JPEG、BMP 或 GIF 文件，或复制 Windows 截图/图片后，直接按 `Ctrl+V` 粘贴。
3. 图片会作为浮动对象显示在表格上方，而不是缩略图。拖动图片可移动到任意表格位置；选中后拖动蓝色八个控制点可调整宽高。
4. 点击“完成并保存”后，导出的 Excel 会保留最终单元格锚点、像素偏移与图片尺寸。

插入或粘贴的图片会复制到 `%LOCALAPPDATA%\CNCProgramSheet\images`，所以原始图片被移动、剪贴板内容被替换或软件升级后，当前会话仍可正常导出。选中图片后按 `Delete` 可移除当前选中的图片。点击合并单元格中的任意位置时，程序会自动使用该合并区域的左上角作为 Excel 图片锚点。

## 解析原则

- 只有在程序头或刀具描述有明确依据时才填写刀具类型、D、R。
- `G41/G42 D1` 这类刀补号不会作为刀具直径。
- 程序头明确写作 `T1 | T5.9 | H1 | D1` 的 T 刀，会在 D 列填写 `T5.9`；后面的 `D1` 不会误作刀具直径。
- `G81/G83/G85` 等固定循环的 `R` 平面不会作为刀具半径。
- 扫描所有实际 Z 值，写入最小值。
- 证据不足时显示“未识别”，等待人工修改。

## 版本、GitHub Release 与自动更新

版本号只维护在 [cnc_program_sheet/version.py](cnc_program_sheet/version.py)。发布步骤：

1. 修改 `__version__`，例如 `1.0.1`，并提交代码。
2. 创建并推送匹配的 Git 标签，例如 `v1.0.1`。
3. `.github/workflows/release.yml` 会在 Windows runner 上运行测试、打包无黑窗 EXE、生成 Inno Setup 安装程序、计算 SHA-256 并发布 GitHub Release。

发布工作流将当前仓库名写入安装包内的更新源，并在每个 Release 附带固定名称的公开更新清单。软件启动后及运行期间每 6 小时会从该公开清单检查最新版本，不消耗 GitHub API 的匿名请求额度；旧版在没有清单时才回退到 API。发现新版本时，下载与 SHA-256 校验均在后台进行，安装前仍由用户确认，避免中断尚未保存的程序单。

GitHub 会自动只保留三个最新的正式 Release 安装包；删除旧 Release 不会删除 Git 源码、标签或影响旧版软件检查并升级到最新版。

数据隔离规则：

- 安装程序仅写入应用安装目录。
- 用户模板、`settings.json`、日志、更新下载文件均在 `%LOCALAPPDATA%\CNCProgramSheet`。
- 安装程序不包含该数据目录，卸载和升级也不会删除或覆盖它。
- 用户“打开模板”选择的外部 `.xlsx` 始终只读；导出始终另存为桌面的新文件。

首次推送到 GitHub 后，把仓库远程地址添加到本地仓库：

```powershell
git remote add origin https://github.com/<owner>/<repository>.git
git add .
git commit -m "feat: initial CNC program sheet desktop app"
git push -u origin main
```

## 验证

```powershell
py -3.12 -m pytest -q
```

测试涵盖模板单元格映射、模板只读复制、文件名防覆盖、刀具 D/R 安全识别、固定循环 R 平面排除和最低 Z 深度扫描。
